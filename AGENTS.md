# Project guidance

## GameDB and conversion data

- Read [README.md](README.md) and [the GameDB recovery guide](docs/gamedb-recovery.md) before changing database resolution, tire selection, wheel sizing, suspension placement, or their fallbacks.
- FH6 GameDB decryption was verified offline on 2026-10-26. A failure of the legacy `CryptoTool.exe` does not establish that FH6 decryption is unavailable. Check the validated cache and the guide before adding more manual approximations.
- Use static file analysis for GameDB recovery. Do not launch or attach to the game, debug it, read its process memory, inject DLLs, install hooks, modify installed game files, or change their permissions. The verified method needs none of those actions or an external upload of game data.
- Prefer the existing database-backed import path when a validated, matching GameDB is available. It supplies stock tire compounds, tire/rim dimensions, wheelbase, tracks, ride heights, and placement offsets. Keep compatibility fallbacks for unavailable data; remove individual overrides only after checking their database replacements and conversion results.
- Resolve cache names through `_decrypted_game_db_cache_path` in [main.py](main.py). Its signature includes the resolved source path, file size, and nanosecond modification time. A cache filename from another install or update is not portable. New caches and source metadata changes are detected by the running wrapper; use a fresh-process status check when diagnosing setup.
- A readable database with a complete stock row for the selected car selects `use_db = True` and `suspension_transform_type = 2` in generated importer scripts; incomplete or missing car data uses compatibility fallbacks. Read-only query coverage does not establish correct Blender geometry. Validate representative conversions before claiming that wheel/tire/suspension output has improved.
- Preserve existing recovery receipts. The verified database passed SQLite page integrity checks but reported 4,131 foreign-key discrepancies; authentication tags were not verified. Do not silently repair or discard database rows on that basis.
- Keep decrypted databases, extracted key values, downloaded binaries, and local receipts in the ignored [workspace/](workspace/) or [temp/](temp/) directories. Commit documentation and key-free implementation code, not those local assets. Record source/output hashes and tool provenance for any new recovery.
- On a cache miss, the wrapper can run the key-free offline FH6 decryptor when `FH6_GAMEDB_KEYS_PATH` names locally provisioned constants and Node.js supports `node:sqlite`. It then tries the legacy crypto tool if available. Keep constants and recovered databases ignored and validate the source-bound receipt before reuse.
